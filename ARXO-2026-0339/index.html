ARXO-2026-0339 · Reported

CSS Animations 1: “the last one in document order wins” for same-name @keyframes does not account for cascade layers

CSS Animations 1 §3 says that of several @keyframes with the same name the last one in document order wins. CSS Cascade 5 §6.4 says @keyframes inside cascade layers use the layer order to resolve collisions, as the Working Group resolved in issue 6404 in 2021. The sentence in CSS Animations 1 was not updated.

Consequence

Cascade 5's own example #example-14540e6d: by Cascade 5 the sidebar animates translate from the override layer; by CSS Animations 1 it animates margin-left from the framework layer, which comes later in the document.

Proposed correction

Let CSS Animations 1 §3 defer to the layer order and keep document order within one layer.

Evidence

Reproduced by execution. Quotations are verbatim from the official material; translations are ours and marked.

If multiple @keyframes rules are defined with the same name, the last one in document order wins, and all preceding ones are ignored.
Normative text · CSS Animations Level 1, Editor's Draft of 13 September 2026 (W3C CSS Working Group) · §3 Declaring Keyframes · Editor's Draft · retrieved 2026-10-30 · SHA-256 a558664f18fc69e909978b802a2cbf5a865897f2eb1f1c02bed6b2845642dfff · copy
At-rules (such as @keyframes, @font-face, @page, etc.) that are defined inside cascade layers also use the layer order when resolving collisions or cascading.
Normative text · CSS Cascading and Inheritance Level 5, Editor's Draft of 13 April 2026 (W3C CSS Working Group) · §6.4 Cascade Layers · Editor's Draft · retrieved 2026-10-30 · SHA-256 2c51fc71d5bfec21aee9acf5004344fc0b5197db31fc48a1ae5373f3fbc4670f · copy
