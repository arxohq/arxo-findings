ARXO-2026-0646 · Reported

EIP-7732: the fork onboarding text still excludes keys of existing validators

EIP-7732 says that at the fork, pending deposits with the builder withdrawal prefix are converted to builders only if their public key does not belong to an existing or pending validator. Pull request 5736 in the consensus specifications, merged on 26 October 2026, changed the onboarding function on purpose: a valid builder deposit registers or tops up a builder even if a validator uses the same key, and a builder deposit for an existing builder tops it up regardless of signature. For a key that already belongs to a validator, the EIP now says the opposite of the specification.

Consequence

A pending deposit with the builder prefix and a valid signature, for the key of an existing validator: by the EIP it is not converted; by the specification it registers a builder.

Proposed correction

Reword the sentence to match the specification: a builder deposit tops up the builder with the same key; otherwise it registers a new builder if its signature is valid, even if a validator uses the same key; other deposits stay in the validator queue.
